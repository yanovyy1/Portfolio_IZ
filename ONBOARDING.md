## Структура проекта

```
index.html          — единственная страница, вся вёрстка тут
css/style.css        — все стили
js/main.js            — курсор, fade-in анимация, модалка проектов
assets/               — PNG-иллюстрации карточек проектов (прозрачный фон,
  плотно обрезаны по контенту — см. «Иллюстрации проектов» ниже)
  freelance.png / prequel.png / other.png / glam.png / 495.png
.github/workflows/deploy.yml — НЕ используется (Pages настроен на classic/legacy branch build,
  этот файл — остаток эксперимента, безвреден, можно игнорировать или удалить)
.nojekyll             — отключает Jekyll-обработку на GitHub Pages
```

## Деплой изменений

Прямо в этой папке:

```bash
git add -A
git commit -m "описание изменений"
git push origin main
```

GitHub Pages сам пересоберёт сайт за ~30–90 секунд (branch build от `main`, папка `/`).
Если после пуша сайт выглядит по-старому — это браузерный кеш, а не баг:
жёсткое обновление (Cmd+Shift+R) или анонимное окно (особенно важно на телефоне).

## Дизайн-система

- **Тема:** тёмная монохромная. Токены в начале `css/style.css`:
  `--bg` (#0a0a0a фон), `--bg-soft`, `--fg` (белый текст), `--fg-dim` (серый), `--line` (бордеры).
- **Шрифты:** Space Grotesk (интерфейс/данные), Inter (мелкий текст), **Caveat** (рукописный —
  заголовок и подписи проектов; обычный регистр, без капители — подобрали под референс
  живой рукописной надписи от пользователя). Подключены через Google Fonts в `<head>` index.html.
- **Layout (десктоп, >720px):** страница жёстко занимает один экран (`.page{height:100dvh}`,
  без скролла) — все 5 фигур гарантированно видны при загрузке. `.stage` (сетка фигур) и
  каждый `.proj-item` имеют `min-height:0`/`min-width:0`, чтобы grid-ячейки могли свободно
  сжиматься под доступную высоту вместо переполнения (иначе браузер применяет
  auto-минимальный размер по контенту и появляется скролл). На очень низких окнах фигуры
  просто пропорционально уменьшаются, а не обрезаются и не вызывают скролл.
- **Layout (мобильный портрет, ≤720px):** здесь `.page{height:auto; min-height:100dvh}` —
  ограничение в один экран сознательно снято, колонка карточек скроллится (см. ниже).
- **Сетка проектов (`.stage`) — десктоп:** 3 колонки × 2 ряда, асимметрично — Freelance
  занимает всю высоту левой колонки (`grid-row: 1 / 3`), во втором ряду середины/правого
  столбца — Glam и 495 Denim. Раскладка задаётся классами `.pi-freelance`, `.pi-prequel`,
  `.pi-other`, `.pi-glam`, `.pi-denim` через `grid-column`/`grid-row`.
- **Мобильный портрет (≤720px):** `.stage` превращается в `display:flex; flex-direction:column`
  — все 5 карточек друг под другом со скроллом, каждая карточка обтягивает свой контент
  (без фиксированной высоты — иначе у «широких» фигур снизу остаётся пустой хвост и зазоры
  между карточками получаются неровными). Порядок карточек на телефоне отличается от
  десктопа и задан через CSS `order` (не трогает DOM/десктоп): 495 Denim → Glam → Prequel →
  Freelance → Other. Мобильный landscape (широкий, но невысокий) — отдельный медиа-запрос,
  там остаётся десктопная 3-колоночная сетка, т.к. по ширине место есть.
- **Карточки проектов:** каждая — кнопка `.proj-item` с подписью (`.proj-name`) и
  PNG-иллюстрацией (`.shape-img`, `object-fit: contain`, drop-shadow, лёгкое увеличение
  при hover/focus). `.shape-wrap` выровнен `align-items: flex-start` — фигура «прилипает»
  к подписи сверху, это то, что делает отступ подпись→фигура одинаковым на всех карточках
  и на всех размерах экрана.
- **Иллюстрации проектов (`assets/*.png`):** ОБЯЗАТЕЛЬНО с прозрачным фоном (alpha-канал) И
  **плотно обрезаны** по фактическому рисунку — без прозрачных полей по краям холста. Если
  в PNG остаётся прозрачный отступ сверху, он складывается с CSS-отступом и расстояние
  подпись→фигура на этой карточке визуально «уезжает» относительно остальных. При замене
  любой из этих 5 картинок — сначала обрезать поле (Preview/Photoshop «Trim», или
  `sips`/скрипт по alpha-bounding-box), потом класть файл с тем же именем в `assets/`.
- **Курсор:** кастомная точка-курсор (`.cursor-dot`, mix-blend-mode difference) на устройствах
  с мышью. Системный курсор скрыт через класс `.has-custom-cursor` на `<html>`, который
  вешает JS только если реально активирован кастомный курсор (без JS — обычный курсор,
  деградация безопасна).
- **Модалка (клик по карточке):** данные берутся из объекта `PROJECTS` в `js/main.js`
  (label/title/role/period/desc/mediaCount). `mediaCount` определяет число плейсхолдер-слотов
  под медиа (вертикальные, 9:16 — под формат Reels/TikTok, плитки `minmax(150px, 1fr)`,
  с иконкой ▶). Модалка скроллится сама (`overflow-y:auto`, `max-height:88dvh`), если
  слотов много (например, 10 у 495 Denim) — это ожидаемо, не баг.

### Медиа в модалках
- **495 Denim, Other, Glam** — реальные видео, подключены через объект `media: [...]`
  (массив имён файлов) в `PROJECTS` (`js/main.js`). `openModal` рендерит для каждого
  элемента `<video controls preload="metadata" playsinline>` с `src="assets/vids/<файл>"`
  и `poster="assets/vids/posters/<файл>.jpg"`. Плейсхолдер (`<div class="media-slot">`
  с текстом «Видео N») остаётся только как fallback, когда у проекта нет `media`.
- **Freelance, Prequel** — медиа ещё не добавлено, модалка показывает 3 плейсхолдер-слота
  по умолчанию (`mediaCount: 3`).

**Видео-файлы (`assets/vids/*.mp4`):** сжаты через ffmpeg — масштаб до ширины ≤720px
(портретный формат), H.264 `preset slow -crf 27`, аудио AAC 128k, `+faststart`.
Так 416 МБ исходников ужались до ~42 МБ (важно — GitHub жёстко режет файлы >100 МБ,
один из исходников был 136 МБ). Оригиналы в максимальном качестве лежат локально в
`assets/vids_originals/` (добавлено в `.gitignore`, в репозиторий не попадает и не
на GitHub — если нужно пересжать заново или архивировать, бери оттуда).

**Постеры (`assets/vids/posters/*.jpg`):** сгенерированы через ffmpeg — кадр на
~15% длительности каждого видео (чтобы не попасть на чёрный вступительный кадр),
масштаб той же ширины ≤720px. Если добавляешь новое видео — не забудь сгенерировать
постер тем же способом и прописать оба пути (`media` + сам файл `.jpg` в `posters/`
с тем же именем, только `.jpg`).

Если понадобится добавить видео для Freelance/Prequel — по той же схеме: положить
`.mp4` в `assets/vids/`, постер в `assets/vids/posters/`, добавить `media: [...]`
в соответствующий объект `PROJECTS`.

## GitHub / деплой — важные детали из истории

- GitHub Pages настроен как **classic (legacy) branch build**, source = `main` / `/`.
  Никакой GitHub Actions не используется — `.github/workflows/deploy.yml` в репо есть,
  но он не задействован (Pages type = legacy, не workflow), это остаток от отладки.
- На аккаунте установлен и авторизован **`gh` CLI** (`brew install gh`, `gh auth login`) —
  им управлялся Pages API, когда обычная настройка через сайт зависала. Обычно это
  больше не нужно, `git push` сам всё пересобирает.
- Если Pages вдруг снова «зависнет» в статусе building и не будет обновляться —
  помогает пересоздать конфиг через API:
  ```bash
  gh api -X DELETE repos/yanovyy1/Portfolio_IZ/pages
  gh api -X POST repos/yanovyy1/Portfolio_IZ/pages -f "source[branch]=main" -f "source[path]=/"
  ```
