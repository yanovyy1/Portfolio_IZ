## Layout-механика: `.proj-list` и `.work-info` — читай перед следующей правкой центрирования

Это самая дорогая (по количеству итераций) часть сессии — **не пытайся
изобрести это заново**, если понадобится что-то менять, отталкивайся от
текущего решения и причин, почему предыдущие варианты не сработали.

**Требование от пользователя:** обе боковые колонки (список проектов слева,
контакты/blurb справа) должны быть **визуально ровно по центру экрана
всегда** — включая самый первый кадр до любого скролла, и без «утекания»
вверх/вниз при скролле.

**Текущее решение (работает):**
```css
.proj-list, .work-info {
  position: fixed;      /* НЕ sticky - см. ниже, почему */
  top: 0;
  height: 100dvh;
  display: flex; flex-direction: column; justify-content: center;
  left: ... / right: ...   /* колонка выше не участвует в flex-раскладке */
  width: clamp(...);
}
```
`.work-track` (центральная лента) компенсирует их отсутствие в
flex-потоке через `padding-left`/`padding-right`, равные ширине колонок +
прежний `column-gap`.

Вордмарк защищён от наложения на центрированные колонки **не подстройкой
их позиции**, а ограничением **своего собственного** размера по высоте
экрана:
```css
.wordmark { font-size: clamp(40px, min(5cqw, 22vh), 125px); }
```
`min(5cqw, 22vh)` — берётся МЕНЬШЕЕ из «% ширины контейнера» и «% высоты
вьюпорта»: на узком ИЛИ на низком окне вордмарк ужимается сам, до того как
дорастёт до центра экрана, где сидит список.

### Почему не `position: sticky`

Первая попытка была `position: sticky; top: 0; height: 100dvh;
justify-content: center` — работает, **не может наложиться** на шапку
(sticky-элемент физически не отрисуется выше своей нормальной позиции в
потоке), но у него две проблемы:
- на самом первом экране (scroll = 0) элемент ещё не «прилип», стоит там,
  куда его поставил обычный поток — то есть **ниже** центра ровно на высоту
  шапки;
- этот сдвиг пропадает, как только пользователь чуть проскроллит — но
  именно требование «всегда, с первого кадра» это не устраивало.

### Почему не `translateY(-50%)` на sticky-элементе

`.proj-list`/`.work-info` несут класс `fade-in` (анимация появления при
загрузке). У `.fade-in.is-visible` есть **своё** правило `transform:
translateY(0)` с специфичностью в 2 класса — оно перебивало наш
`transform: translateY(-50%)` (1 класс) сразу после анимации появления.
Даже если поднять специфичность (`.proj-list.fade-in.is-visible`),
`transform` — визуальный эффект, применяется **всегда**, в том числе пока
sticky ещё не «прилип», то есть утаскивал список вверх, под тэглайн, на
первом экране. Отсюда и переход на `height: 100dvh` + `justify-content:
center` — центрирование через раскладку, а не через transform.

### Почему не `position: fixed` + JS-измерение высоты шапки

Промежуточный вариант: `position: fixed`, но `top`/`height` считались от
CSS-переменной `--header-h`, которую JS выставлял через
`workStageEl.offsetTop` — центрирование происходило в свободном
пространстве **под** шапкой, а не по всему экрану. Работало без наложений,
но давало **постоянное** смещение от истинного центра размером в половину
высоты шапки — причём это смещение не пропадало при скролле (в отличие от
sticky-варианта, где после скролла было 0 смещения). Отклонено как
объективно худшее для времени, когда пользователь реально проскроллил в
середину ленты проектов (что бывает почти всегда).

**Итог, который сработал:** `position: fixed` (не sticky — центрирование
нужно и на первом кадре) + защита от наложения через `min(cqw, vh)` на
самом вордмарке (не через позицию/отступ колонок — тогда наложение
невозможно по построению, а не «пока помещается»).

### Известное ограничение

На **очень низких** окнах (примерно ≤300–350px высоты вьюпорта — например,
телефон в альбomной ориентации, у которого ширина остаётся больше
мобильного брейкпоинта 720px) список из 5 строк физически не сжимается
вместе с вордмарком (у него нет `vh`-масштабирования), и лёгкое наложение
всё ещё возможно. Пользователь про этот сценарий пока не спрашивал — если
спросит, потребуется отдельная `@media (max-height: ...)` обработка,
независимая от брейкпоинта по ширине.

### Не забыть при следующей правке центрирования

- Мобильный сброс (`@media max-width:720px`) обнуляет `position`, `top`,
  `left`, `right`, `width`, `height`, `justify-content` для обеих колонок
  — если поменяешь набор свойств в десктопной версии, обнови и сброс,
  иначе фиксированная ширина/позиция «протечёт» в мобильную вёрстку.
- `.work-track`'ов `padding-left`/`padding-right` должен математически
  совпадать с шириной колонок + прежним `column-gap` — если поменяешь
  `clamp(...)` ширины колонки, поменяй и paddings в `.work-track`.

## Дизайн-система

### Токены (`css/style.css`, `:root`)

| Токен | Светлая | Тёмная | Назначение |
|---|---|---|---|
| `--bg` | `#f7f6f2` | `#121110` | фон страницы |
| `--bg-soft` | `#eeece4` | `#1d1c19` | плейсхолдер превью-кадра |
| `--fg` | `#0a0a0a` | `#f5f3ee` | основной текст |
| `--fg-dim` | `#6b6a62` | `#8f8c80` | второстепенный текст (**не** `#85837a` — это старое значение проваливало WCAG AA, 3.51:1 вместо нужных 4.5:1; текущее даёт ~5:1) |
| `--line` | `#dedbd1` | `#2e2c27` | тонкие границы |

**Тёмная тема** переключается атрибутом `data-theme="dark"` на `<html>`
(`js/main.js`, кнопка `#themeToggle`), сохраняется в `localStorage` под
ключом `theme`. Никакого `prefers-color-scheme` — по умолчанию всегда
светлая, пока пользователь явно не переключит. Инлайн-скрипт в `<head>`
index.html применяет сохранённую тему **до** первой отрисовки (иначе
мигание светлым при перезагрузке в тёмном режиме).

### Шрифты

Montserrat (500–800, интерфейс/заголовки/вордмарк) + Inter (300–500,
мелкий текст), подключены через Google Fonts. Caveat (рукописный) убран
полностью в редизайне — не путать со старой тёмной версией, где он был
акцентным.

### Курсор

Кастомная точка (`.cursor-dot`), `mix-blend-mode: difference`, залита
**фиксированным белым** (`#ffffff`), не токеном — это единственный способ
получить видимый контраст на любом фоне (в т.ч. на обеих темах): difference
белого с тёмным фоном даёт светлый результат, с светлым фоном — тёмный.
Скрыт на тач-устройствах (`hover: none`).

### Layout: три колонки

1. **`.proj-list`** (слева) — список проектов, генерируется JS из массива
   `ORDER` в `js/main.js`. **Порядок проектов на сайте меняется правкой
   ТОЛЬКО этого массива.** `position: fixed`, всегда по центру экрана — см.
   раздел «Layout-механика» выше **обязательно** перед правкой этого блока.
2. **`.work-track`** (по центру) — вертикальная лента, тоже из `ORDER`.
   Каждый слайд: превью (постер+видео, автоплей при активации через
   `IntersectionObserver`), подпись роли (`.preview-role`, вертикальный
   текст, **справа** от кадра — не слева, как было раньше), CTA «VIEW CASE
   STUDY →» под превью, оверлей «VIEW PROJECT» на hover.
   Подписи периода/лейбла (`.preview-meta`) больше нет — убрана по просьбе
   пользователя.
3. **`.work-info`** (справа) — блёрб + контакты + `.work-active` («Viewing:
   <название текущего проекта>», синхронизировано с активным пунктом списка
   через `setActive()` в `js/main.js`). `position: fixed`, тоже всегда по
   центру. На мобильном `.work-active` скрыт (нет понятия «активного»
   проекта в статичном списке).

### Мобильная версия (≤720px)

`.work-track` скрыт полностью — на его месте статичный список
(`.proj-row` с `.proj-row-thumb`, **84px** шириной 9:16). Превью **не**
статичные: `IntersectionObserver` (`rowIO` в `js/main.js`) лениво
подгружает и проигрывает видео каждой строки при попадании в вьюпорт —
поэтому даже на мобильном сайт показывает motion, а не просто фотогалерею.
Тап по строке сразу открывает модалку (скроллить уже некуда). Часы в
top-nav скрыты (не нужны на узком экране). Кнопка темы получила увеличенный
tap-target (padding + компенсирующий отрицательный margin) — была слишком
мала и упиралась в зону edge-swipe жеста iOS.

### Медиа в модалках

Единая сетка 3×3 на десктопе (2×2 на мобильном) для всех проектов —
`mediaCount: 9`, недостающие слоты дорисовываются плейсхолдерами. Видео
сжаты через ffmpeg (≤720px ширина, H.264 `crf 27`). Постеры — **имя видео
с обрезанным `.mp4`**, не с добавленным `.jpg` (`freelance_5.mp4` →
`freelance_5.jpg`) — перепутать легко, не даёт ошибки в консоли, просто
показывает пустой кадр.

Если добавляешь новое видео: сжать → `assets/vids/`, сырой оригинал →
`assets/vids_originals/` (гитигнор), постер с правильным именем →
`assets/vids/posters/`, добавить в `media: [...]` нужного проекта —
**первый элемент массива** становится превью на главной странице и в
мобильном списке.

## Локальное тестирование — важные грабли

- **Кеш Safari на localhost очень упрямый.** Обновление CSS/JS иногда НЕ
  подхватывается даже через Cmd+Shift+R или явный reload — надёжнее всего
  каждый раз поднимать http-сервер на **новом порту**
  (`python3 -m http.server ПОРТ`), не переиспользовать старый. Наступали на
  это несколько раз за сессию — при отладке layout-проблемы стоит сразу
  проверить, не кеш ли это, прежде чем чинить несуществующий баг.
- **Скриншоты через `screencapture -R` могут захватить не то окно.** В этой
  среде окно IDE (Claude Code) иногда перехватывает фокус между
  bash-командами — перед серией скриншотов стоит явно проверить
  `osascript -e 'tell application "System Events" to name of first process
  whose frontmost is true'` равно `Safari`, а не слепо доверять
  предыдущему `activate`.
- **Клики/скролл**: `cliclick c:X,Y` (точки экрана) для кликов,
  `osascript ... key code 121/116/115/119` для Page Down/Home/Down/End.
  Координаты из скриншотов — в retina-пикселях (обычно ×2 от точек), а
  `cliclick` ждёт точки — пересчитывать через `bounds of front window`.
- **`do JavaScript` в Safari через osascript не работает** без ручного
  включения чекбокса в Developer-настройках — полагайся на скриншоты +
  `key code`/`cliclick`, не на выполнение произвольного JS.
- Резиз окна: `osascript -e 'tell application "System Events" to tell
  process "Safari" to set size of front window to {W, H}'` — надёжно, но
  первая попытка после смены URL иногда падает, просто активируй Safari и
  повтори.

## Особенности среды

- Node.js/npm ставится через `brew install node` без проблем, но `npx
  <пакет>` может падать `ECONNRESET` на загрузке тела npm-пакета даже при
  рабочей сети (curl/git по HTTPS ок) — обходной путь: `git clone --depth 1
  --filter=blob:none --sparse` нужного репозитория + `sparse-checkout set`.
- Других браузеров кроме Safari на машине нет.
- PIL (`python3 -c "import PIL"`) доступен — использовался для точной
  обрезки/сжатия скриншотов при сборке дизайн-аудита, `sips` для этого
  оказался менее предсказуем (`--cropOffset` работал не так, как ожидалось).

## Возможные следующие шаги

1. Ничего срочного не висит — все правки этой сессии запушены в `main` и
   задеплоены.
2. Если пользователь пожалуется на **наложение вордмарка на список на
   очень низком окне** (например, телефон в альбомной ориентации) — читай
   раздел «Известное ограничение» выше, потребуется отдельный
   `@media (max-height: ...)`.
3. `redesign/obys-style` ветка всё ещё не удалена — можно почистить
   локально и на origin, если пользователь не попросит сохранить.
4. Если пользователь попросит что-то из старого тёмного дизайна — смотри
   `backup/original-dark-design`, не обязательно «всё или ничего».
